# Delivery documentation

## Goal
Generate .docx documents ready to deliver to the client, with a fixed structure, standardized formatting and content faithful to what was built.

## When to use
- At the end of Arc: after the selection report or the case documentation, ask whether the user wants the document. If so, generate it in the template.
- At the end of Smith: after the agent is created, ask whether the user wants the Creation Guide. If so, generate it in the template.
- Command gerar discovery: generates the Case Selection (several cases not yet chosen) or the Case Document (single or already chosen case).
- Command gerar entrega: generates the Agent Creation Guide.
- Formalization with the client after the discovery call: email and Teams message.

## Absolute rule
Never invent client data, cases, sources, screen paths or buttons. If information is missing, ask before generating. Creation steps in the platform must be confirmed in the Microsoft Learn MCP (and in the platform skill) at generation time.

## Flow: Arc documents
1. Ask whether the user wants the document. Proceed only with confirmation.
2. Choose the template: several cases without the client's choice, references/modelo-selecao.md; single or chosen case, references/modelo-case.md.
3. Collect what is missing: client name, area or session, meeting date and responsible consultant.
4. Use the cases already documented by the arc-cases skill; do not rewrite the content.
5. Apply references/regras-formatacao.md and generate the .docx with Code Interpreter through the scripts/brand_docx.py script, in the brandbook standard.
6. Deliver the file for download and offer to prepare the formalization email.

## Flow: Creation Guide
1. Ask whether the user wants the Creation Guide. Proceed only with confirmation.
2. Identify the platform: Copilot Chat, Agent Builder, Agents Toolkit, Copilot Studio or Copilot Notebooks.
3. Collect what is missing: client, agent name and function, purpose, interaction logic, instructions (smith-prompt Base Prompt), knowledge sources, capabilities, skills, sustainment and whether the agent is robust enough to need the guidance prompt (section 8.2).
4. Load the platform skill and consult the Microsoft Learn MCP for the up-to-date step by step.
5. Adapt the sections according to references/documentacao-por-tipo-agente.md.
6. Build the document in the structure of references/modelo-entrega.md.
7. Apply references/regras-formatacao.md, with a copy block on all content to copy and paste, and generate the .docx with Code Interpreter through the scripts/brand_docx.py script.
8. Deliver the file for download.

## Flow: formalization
Formalization happens after the discovery call, always with an attached document:
- One case: email with the case document.
- Several cases: first email with the selection document; after the client's decision, a new email with the chosen case document.

1. Collect what is missing: recipients, people in copy and the name of the document to attach.
2. Write the complete email: subject, greeting, context of the call, summary of what was decided or what the client needs to decide, next steps and closing. No signature: the user's Outlook applies theirs.
3. With `EmailActions`, create the email as a draft in the user's Outlook. Never send it, even if the user asks to send it directly: sending is always the user's action.
4. If the draft cannot be created, deliver recipients, subject and body in a copyable box.
5. Tell the user to review, attach the document and send.
6. If the user asks for a Teams message, deliver it in a copyable box: ArcSmith does not send Teams messages.

## Rules
- Always ask before generating a document.
- Every document carries the Cloud Target logo, the client name, title, subtitle, date and key points and follows the AI brandbook (references/regras-formatacao.md).
- Didactic, accessible language in the Creation Guide; objective in the Case Selection and the Case Document.
- Keep the instructions exactly as generated by the smith-prompt skill.
- Section 3 (interaction logic): step by step for sequential flow agents; main usage types for free interaction agents.
- Section 8.2: only for robust agents.
- No emojis, comments, usage instructions or meta-information in the final document.
- If the .docx fails, offer the content in markdown for the user to paste into Word and state the limitation.
