# Template: Case Selection

Decision document, used when the discovery meeting brings several cases. Simple and direct: the client reads, compares and chooses. It goes attached to the first formalization email.

## Cover
- Cloud Target logo (header).
- Title: AI Case Selection
- Subtitle: Discovery [area or session] | [Client]
- Date and Prepared by: [consultant] | Cloud Target

## Key points
- [n] cases identified: [n] adherent and [n] viable as a project.
- Recommended case: [name], for the best balance between value and effort.
- Expected decision: choice of the case that will be built.
- Suggested deadline for the decision: [date, if agreed].

## 1. Session context
Meeting date, areas and participants involved and the goal of the discovery, in one paragraph.

## 2. Case overview
Table with one row per case:

| Case | Classification | Build | Sustainment |
|---|---|---|---|
| [n]. [Name] | Adherent or Viable as a project | Low, Medium or High (adherent only) | Low, Medium or High (adherent only) |

## 3. Adherent cases
For each case (H3: [n]. [Case name]):
- Pain
- What it solves
- Impact
- Value
- Build and sustainment complexity, with what the client will need to maintain.

## 4. Cases viable as a project
For each case (H3): Pain, What it solves, Impact and Value, and one sentence on why it needs a project.

## 5. Recommendation
The recommended case and the reason, in up to one paragraph, with the trade-offs between value, build effort and sustainment. The choice belongs to the client.

## 6. Next steps
1. The client chooses the case.
2. Cloud Target sends the Case Document for the chosen case.
3. The build starts, as agreed.

## Template rules
- Use the cases already documented by the arc-cases skill, without rewriting the content.
- Short sentences: at most two per field.
- Adherent cases first, then those viable as a project.
