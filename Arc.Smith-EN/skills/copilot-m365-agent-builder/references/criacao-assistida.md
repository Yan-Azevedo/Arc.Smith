# Assistant mode: creation through the Agent Builder conversation

## How the creation conversation works (Describe tab)
- The user describes the agent in natural language and Agent Builder configures automatically: name, description, instructions (with guidelines, steps, error handling and examples), knowledge sources and suggested prompts.
- Agent Builder suggests and applies refinements. Code Interpreter and the image generator are available automatically.
- When the client's level supports skills (confirm in the feature check), Agent Builder creates skills from a natural language description. The created skill appears in the Configure tab, under Skills.
- The instructions are generated by Agent Builder: the brief guides the content, but there is no documented guarantee that the text will be used literally. That is why the post-creation checklist requires checking.
- Generic sources are inferred from the description (example: asking to summarize emails adds "My emails"). Specific files, sites and lists must be attached with the + button of the message box (Add work content, Upload images and files, Attach cloud files) or in the Configure tab.
- After creation, the agent can be refined in natural language.
- The character limit of a message in the creation conversation is not documented. If the brief is rejected or cut, split it into two messages: first identity and instructions, then sources, capabilities, skills and prompts.

## Interview (before the brief)
Run a conversation, not a fixed questionnaire. One stage per message, with questions adapted to what the user has already answered and to the case documented in Arc, if any. Do not ask what has already been answered. When the user does not know, offer two or three options and recommend one. Never fill in an answer on your own.

| Stage | What to gather |
|---|---|
| 1. Purpose | Problem the agent solves, goal, who will use it and the level (Copilot Basic or Premium). |
| 2. Flow | How the conversation starts, what the agent asks the user, the steps it performs, the business rules, what to do when information is missing and what the agent must not do. |
| 3. Output | Tone, language, length and format of the answer (text, bullets, table, document). An example of a good answer, if the user has one. |
| 4. Knowledge sources | Which sources, what each one is for and whether the agent should prioritize only the given sources. Respect the client's level. |
| 5. Capabilities | Whether the agent creates documents, charts and code (Code Interpreter) and whether it creates images. |
| 6. Skills (if the check confirms) | Tasks that always repeat with the same steps: goal, fixed steps, output format and supporting files (skills-agente.md file of the smith-prompt skill). |
| 7. Name and prompts | Name (up to 30 characters), description and 4 to 6 suggested prompts. |
| 8. Tests | Questions to test the agent and what a correct answer would be. |

At the end, present a short summary of the decisions and ask for confirmation before generating the brief.

## Brief (a single copyable box)
Build the Base Prompt with the smith-prompt skill and deliver the brief in this structure, all in the same box:

```
Create an agent with the configuration below. Use exactly the name, description, instructions and suggested prompts provided, without rewriting them.

Name: [up to 30 characters]

Description: [up to 1,000 characters]

Instructions (use exactly this text in the Instructions field):
[complete Base Prompt, up to 8,000 characters]

Knowledge sources:
- [source]: [what the agent uses this source for]

Capabilities:
- Create documents, charts and code: [yes or no]
- Create images: [yes or no]

Skills (create each one as a reusable skill):
1. Name: [skill-name]
   Goal: [what the skill delivers]
   When to use: [user request that triggers the skill]
   Fixed steps: [step 1; step 2; step 3]
   Output format: [format]
   Supporting files: [templates or data, if any]

Suggested prompts:
1. Title: [title] | Message: [prompt text]
2. Title: [title] | Message: [prompt text]
3. Title: [title] | Message: [prompt text]
4. Title: [title] | Message: [prompt text]
```

Brief rules:
- List only sources and capabilities available for the client's level.
- Include the Skills section only if the feature check confirms support for the client's level. Otherwise, remove the whole section.
- For each specific source (file, site, list), make it clear in the checklist that it must be attached.
- Do not include in the brief settings that only exist in the Configure tab.

## Post-creation checklist
Deliver right after the brief box:
1. In the Configure tab, check name, description and instructions. If the instructions were rewritten, replace them with the Base Prompt that is in the brief.
2. If the agent has skills, check under Skills whether each skill was created and review its content. If a skill was not created, ask ArcSmith for its .zip package (Detailed mode) and upload it under Skills, Add.
3. Attach the specific sources with the + button or in the Knowledge section, respecting the limits.
4. Adjust what only exists in the Configure tab: icon, response mode (Auto, Quick response or Think deeper), "Only use specified sources", "Search all websites" and "Reference people in organization".
5. Test in the Try it tab with the suggested prompts and the interview's test questions; confirm the answers use the expected sources and skills.
6. Select Create.
