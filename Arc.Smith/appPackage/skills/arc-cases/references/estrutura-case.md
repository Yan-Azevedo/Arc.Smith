# Estrutura do case

## Formato completo (case único ou case escolhido)
Numere: "Caso 1 – [nome]".

| Seção | Conteúdo |
|---|---|
| **Apresentador e Área** | Quem apresentou o caso e de qual área. Se não foi mencionado: [não informado]. |
| **Caso apresentado** | O processo ou a situação relatada, como acontece hoje. |
| **Dor** | O gargalo ou a dor principal do processo atual. |
| **Objetivo** | O que a solução deve alcançar. |
| **O que resolve** | O efeito direto da solução sobre a dor. |
| **Impacto** | Quem e quanto o case afeta: área, volume, frequência, tempo ou risco, conforme relatado. |
| **Valor** | Benefício concreto e específico da construção, sem generalizações. |
| **Classificação** | Aderente ou Viável em projeto (complexidade.md). |
| **Complexidade de construção** | Baixa, Média ou Alta, com justificativa. Só para case aderente. |
| **Complexidade de sustentação** | Baixa, Média ou Alta, com justificativa e o que o cliente precisará manter. Só para case aderente. |

## Formato resumido (relatório de seleção)
Usado quando a reunião traz vários cases. Um bloco por case, na ordem: aderentes primeiro, depois os viáveis em projeto.

| Campo | Conteúdo |
|---|---|
| **Case** | Número e nome. |
| **Dor** | Uma ou duas frases. |
| **O que resolve** | Uma ou duas frases. |
| **Impacto** | Uma frase. |
| **Valor** | Uma frase. |
| **Classificação** | Aderente (construção X, sustentação Y) ou Viável em projeto. |

Ao final do relatório, um resumo: total de cases, quantos aderentes e quantos viáveis em projeto.

## Regras de preenchimento
- Cada case é uma unidade independente, mesmo que surja na mesma entrevista ou área de outro.
- Escreva com base no que foi relatado; não invente sistemas, integrações, participantes ou números.
- Campo sem informação: [não informado].
- Não mencione o tipo de solução (prompt, agente, projeto) no texto do case.
